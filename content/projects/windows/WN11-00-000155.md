# STIG ID: [WN11-00-000155](https://stigaview.com/products/win11/v2r5/WN11-00-000155/)
## Vulnerability Discussion
Windows PowerShell 5.0 added advanced logging features which can provide additional detail when malware has been run on a system. Disabling Windows PowerShell 2.0 mitigates against a downgrade attack that evades the Windows PowerShell 5.0 script block logging feature.

## Compliance Check
Run "Windows PowerShell" with elevated privileges (run as administrator) and enter the following:
```powershell
Get-WindowsOptionalFeature -Online | Where FeatureName -like *PowerShellv2*
```

If either of the following have a "State" of "Enabled", this is a finding.
```
FeatureName : MicrosoftWindowsPowerShellV2
State       : Enabled

FeatureName : MicrosoftWindowsPowerShellV2Root
State       : Enabled
```

Alternately: Search for "Features" and select "Turn Windows features on or off". If "Windows PowerShell 2.0" (whether the subcategory of "Windows PowerShell 2.0 Engine" is selected or not) is selected, this is a finding.

## Remediation
Disable "Windows PowerShell 2.0" on the system. Run "Windows PowerShell" with elevated privileges (run as administrator) and enter the following:
```powershell
Disable-WindowsOptionalFeature -Online -FeatureName MicrosoftWindowsPowerShellV2Root
```

This command must disable both `MicrosoftWindowsPowerShellV2Root` and `MicrosoftWindowsPowerShellV2`, which correspond to "Windows PowerShell 2.0" and "Windows PowerShell 2.0 Engine" respectively in "Turn Windows features on or off".

Alternately: Search for "Features". Select "Turn Windows features on or off". De-select "Windows PowerShell 2.0".

## Powershell Remediation Script
```powershell
# Check for administrative privileges
if (-not ([Security.Principal.WindowsPrincipal] [Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole] "Administrator")) {
    Write-Error "This script requires administrative privileges. Please run PowerShell as an administrator."
    exit
}

# Check the current state of PowerShell 2.0 features
Write-Output "Checking current state of Windows PowerShell 2.0 features..."
$Features = Get-WindowsOptionalFeature -Online | Where-Object FeatureName -like *PowerShellv2*

foreach ($Feature in $Features) {
    Write-Output "Feature: $($Feature.FeatureName) | State: $($Feature.State)"
}

# Disable PowerShell 2.0 Root feature (disables both Root and Engine)
$RootFeature = $Features | Where-Object FeatureName -eq "MicrosoftWindowsPowerShellV2Root"

if ($RootFeature.State -eq "Enabled") {
    Write-Output "Disabling MicrosoftWindowsPowerShellV2Root..."
    Disable-WindowsOptionalFeature -Online -FeatureName MicrosoftWindowsPowerShellV2Root -NoRestart
} else {
    Write-Output "MicrosoftWindowsPowerShellV2Root is already disabled. No action required."
}

# Verify both features are disabled
Write-Output "Verifying the state of Windows PowerShell 2.0 features..."
$Features = Get-WindowsOptionalFeature -Online | Where-Object FeatureName -like *PowerShellv2*

foreach ($Feature in $Features) {
    if ($Feature.State -eq "Disabled") {
        Write-Output "Verification successful: $($Feature.FeatureName) is Disabled."
    } else {
        Write-Error "Verification failed: $($Feature.FeatureName) is not disabled. Current state: $($Feature.State)."
    }
}

# Force Group Policy update
Write-Output "Enforcing Group Policy update..."
gpupdate /force
```
